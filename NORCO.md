# Norco Remote

Norco's branded build of the [RustDesk](https://github.com/rustdesk/rustdesk) Android client,
used by the Norco IT helpdesk for **attended** remote support of company phones.

- Upstream: `rustdesk/rustdesk`, tag **1.5.1** (the same version as Norco's desktop clients).
- Branch: `norco` (this fork's default branch) = tag `1.5.1` + the patches listed below.
  `master` is left as upstream's.
- License: AGPL-3.0, same as upstream. This repository is the complete corresponding source of
  every Norco Remote APK that is distributed.
- What it changes: the app talks only to Norco's own server (built in, not editable), has its
  own name, icon and application ID `com.norco.remote`, accepts incoming sessions only, and has
  a shorter first run.

Nothing secret is in this repository. The server key in `src/norco.rs` is the server's *public*
key. The signing keystore and its passwords exist only with the keystore owner and as GitHub
Actions secrets.

## Building

Actions > **Norco Remote Android** > **Run workflow** (branch `norco`). About an hour the first
time, less once the caches are warm. The signed APK is the run's artifact
`norco-remote-<version>-b<run>-arm64`, and the run summary shows its application ID,
versionCode and signing-certificate fingerprint. Pushing a tag named `norco-v*` starts the same
build.

- Only arm64 is built. Every phone in the fleet is arm64.
- `versionCode` is `2000 + <workflow run number>`, so every build can be uploaded to Managed
  Google Play as an update of the previous one. If this workflow file is ever renamed, the run
  number restarts at 1; raise `--build-number` in the workflow by hand in that case.
- Managed Google Play private apps take an APK, so no AAB is built.

### Signing (one-time setup by the keystore owner)

Create the keystore on your own computer (needs a JDK for `keytool`). Use one password of
letters and digits for both prompts, and keep the file and password somewhere safe and backed
up: **every later update must be signed with this same key**, and a lost key means a new
application ID and a reinstall on every phone.

```
keytool -genkeypair -v -keystore norco-remote-release.jks -storetype PKCS12 -alias norco-remote -keyalg RSA -keysize 4096 -validity 10950 -dname "CN=Norco Remote, O=Norco Inc, C=US"
```

Turn it into one line of base64 for GitHub:

```
# PowerShell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("norco-remote-release.jks")) | Set-Clipboard
# Linux / macOS / Git Bash
base64 -w0 norco-remote-release.jks
```

Then add four repository secrets under Settings > Secrets and variables > Actions:

| Secret | Value |
|---|---|
| `ANDROID_SIGNING_KEY` | the base64 text of the `.jks` file |
| `ANDROID_ALIAS` | `norco-remote` |
| `ANDROID_KEY_STORE_PASSWORD` | the keystore password |
| `ANDROID_KEY_PASSWORD` | the same password (a PKCS12 keystore uses one password for both) |

Without these secrets the workflow still runs and produces
`…-DEBUG-SIGNED.apk`, signed with a throw-away key. That file only proves the build works. Do
not hand it out or upload it: a phone that has it must uninstall it before the real one can be
installed.

## Patched files

Everything below is the whole difference from upstream tag `1.5.1`
(`git diff 1.5.1 norco --stat`). Lines changed inside upstream files carry a `NORCO` comment.

| File | Change |
|---|---|
| `src/norco.rs` (new) | All runtime defaults: app name, ID/relay server, API server, server public key, one-time-password-only, first-run defaults, incoming-only on Android. |
| `src/lib.rs` | `pub mod norco;` |
| `src/flutter_ffi.rs` | `crate::norco::apply();` as the first line of `initialize()` and of `Java_ffi_FFI_startServer()` (the two entry points on Android). |
| `flutter/android/app/build.gradle` | `applicationId "com.norco.remote"`. `namespace` stays `com.carriez.flutter_hbb`. |
| `flutter/android/app/src/main/AndroidManifest.xml` | App label `Norco Remote`, accessibility service label `Norco Remote Input`, deep-link scheme `norcoremote` (so it does not claim `rustdesk://` links). |
| `flutter/android/app/src/main/res/values/strings.xml` | App name in the three strings. |
| `flutter/android/app/src/main/kotlin/com/carriez/flutter_hbb/MainService.kt` | Notification title and channel name. |
| `flutter/android/app/src/main/kotlin/com/carriez/flutter_hbb/BootReceiver.kt` | Toast text. |
| `flutter/android/app/src/main/res/mipmap-*/ic_launcher*.png`, `ic_stat_logo.png` | Norco icons, generated by `norco/make_icons.py`. |
| `flutter/android/app/src/main/res/mipmap-anydpi-v26/ic_launcher*.xml` | Removed the `<monochrome>` layer (a full-colour logo makes a solid blob as a themed icon). |
| `flutter/android/app/src/main/res/values/ic_launcher_background.xml` | Icon background colour. |
| `flutter/lib/models/server_model.dart` | `toggleService()`: no log-folder and file-transfer-folder pickers before the first start when incoming-only. |
| `flutter/lib/mobile/pages/home_page.dart` | Opens on **Share screen** (and Back returns there) when incoming-only. |
| `.github/workflows/norco-android.yml` (new) | The build. A cut-down copy of upstream's `build-rustdesk-android` job. |
| `norco/make_icons.py` (new) | Icon generator. |
| `NORCO.md` (new) | This file. |

`libs/hbb_common` (a submodule) is **not** forked or patched. `src/norco.rs` fills the same
in-memory option tables that upstream's own signed "custom client" configuration fills, so the
upstream constants `RENDEZVOUS_SERVERS` and `RS_PUB_KEY` are never reached.

Why the Kotlin package was not renamed: the Rust library exports JNI functions named after the
Kotlin classes (`Java_ffi_FFI_*`, `Java_com_carriez_flutter_1hbb_DocumentLogs_setEnabled`), and
Android only needs `applicationId` to be unique. Leaving the package alone keeps dozens of files
identical to upstream.

### What `src/norco.rs` sets

| Setting | Value | Kind |
|---|---|---|
| ID / rendezvous server, relay server | `itinventory.norco-inc.com` | fixed |
| API server | `https://itinventory.norco-inc.com` | fixed |
| Server public key | `Fn4XaHrSvJgqkDV8rov+RsYegwN8XsRa+zszuHr1MVE=` | fixed |
| `verification-method` | `use-temporary-password` (the on-screen one-time password only; no permanent password) | fixed |
| `show-scam-warning` | off | default |
| `disable-floating-window` | on (no "Display over other apps" request) | default |
| `conn-type` | `incoming` (Android only: the "connect to another device" tab is hidden) | fixed |

"Fixed" values cannot be changed in the app and override anything saved on the device.
"Default" values apply until the user changes them in Settings. If the server host or key ever
changes, edit this one file and rebuild.

### Repository settings that are not in git

- Default branch is `norco`.
- Actions are enabled. Upstream's workflows that start by themselves (CI, Full Flutter CI,
  Flutter Nightly Build, Flutter Tag Build, Fdroid, playground, Clear cache, Update
  webpki-roots) are **disabled** under Actions so they do not run here. `bridge.yml` stays
  enabled because the Norco workflow calls it.
- The four signing secrets above.

## Moving to a new upstream release

Do this when the desktop clients move to a new RustDesk version, or when an Android fix is
needed. Replace `1.5.1` / `X.Y.Z` with the old and new tags.

```
git fetch upstream tag X.Y.Z
git checkout norco
git rebase --onto X.Y.Z 1.5.1 norco
git submodule update --init --recursive
```

Then check, in this order:

1. **Conflicts.** The likely ones are the two Dart files and `flutter_ffi.rs`. Each patched
   spot has a `NORCO` comment; re-apply the same few lines by hand.
2. **`src/norco.rs` still compiles against the new `hbb_common`.** It uses
   `config::APP_NAME`, `OVERWRITE_SETTINGS`, `DEFAULT_LOCAL_SETTINGS`, `HARD_SETTINGS` and the
   option names in the table above. Search the new tag for each if the build fails.
3. **The workflow.** Compare upstream's `build-rustdesk-android` job and the `env:` block in
   `.github/workflows/flutter-build.yml` at the new tag with `norco-android.yml`, and copy any
   changed versions (`RUST_VERSION`, `ANDROID_FLUTTER_VERSION`, `NDK_VERSION`,
   `VCPKG_COMMIT_ID`, `CARGO_NDK_VERSION`), action pins or steps.
4. **New first-run prompts.** Read `toggleService()` in `flutter/lib/models/server_model.dart`
   at the new tag for anything new that appears before the service starts.
5. `git push --force-with-lease origin norco`, run the workflow, then install the APK over the
   previous one on a test phone and repeat the test in the helpdesk walk-through.
6. Update the version in the first section of this file and in this section's commands.

New icons: `python norco/make_icons.py <square-logo.png> --background "#000000" --badge 0.9`
(needs Pillow), then commit the changed files under `flutter/android/app/src/main/res`.

Known upstream Android fixes that are in 1.5.3 but not in 1.5.1: copy captured frames before the
`Image` is released (rustdesk/rustdesk#16827, shows as black or stale rectangles in the remote
view) and a crash on clipboard payloads over 1 MB (#16767). If either shows up on the fleet,
move to 1.5.3 or later.
